# Railway Environment Variables Checklist

## ⚠️ CRITICAL - Database Configuration

Make sure these are set in Railway → Your Backend Service → Variables:

```env
# CRITICAL: This tells Laravel to use MySQL
DB_CONNECTION=mysql

# These should reference your Railway MySQL service
DB_HOST=${{MySQL.MYSQL_HOST}}
DB_PORT=${{MySQL.MYSQL_PORT}}
DB_DATABASE=${{MySQL.MYSQL_DATABASE}}
DB_USERNAME=${{MySQL.MYSQL_USER}}
DB_PASSWORD=${{MySQL.MYSQL_PASSWORD}}
```

## 🔍 How to Verify in Railway:

1. Go to your Railway project
2. Click on your **Backend Service** (LegalKonect)
3. Click on **"Variables"** tab
4. Look for `DB_CONNECTION` - it MUST be set to `mysql`
5. Verify the MySQL variables exist (`${{MySQL.MYSQL_HOST}}`, etc.)

## ⚠️ Common Mistake:

If you see the error mentions "sqlite" in logs, it means:
- `DB_CONNECTION` is NOT set to `mysql` in Railway
- OR the variable is misspelled
- OR MySQL service is not linked properly

## 🔧 How to Fix:

### Option 1: Add/Update Variables Manually
1. In Railway → Backend Service → Variables
2. Click "+ New Variable"
3. Add: `DB_CONNECTION` = `mysql`
4. Verify MySQL reference variables exist
5. Click "Deploy" to redeploy

### Option 2: Link MySQL Service Properly
1. Make sure you created a MySQL database in Railway
2. In your backend service, the MySQL service should be visible
3. Railway automatically creates `${{MySQL.*}}` variables when services are linked

## ✅ Verification Steps After Fix:

1. Check Railway logs after deployment
2. Look for: `INFO  Running migrations.`
3. Migrations should complete without SQLite errors
4. You should NOT see "no such function: GETDATE" anymore

## 📝 Note:

Your local `.env` uses SQL Server (`DB_CONNECTION=sqlsrv`), which is fine for local development.
Railway uses MySQL (`DB_CONNECTION=mysql`), which is configured via Railway's environment variables.
They don't conflict because they're separate environments.
